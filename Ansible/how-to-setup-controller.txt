F1.sh - IRSeC ANSIBLE DEPLOYMENT GUIDE
====================================
WEBSITE: https://f1-sh.duckdns.org
REPO: https://github.com/austinbenedicto/IRSEC

IMPORTANT: https://f1-sh.duckdns.org is your WEBSITE, not necessarily a ZIP.
These commands ASSUME you publish the toolkit as:
https://f1-sh.duckdns.org/irsec-toolkit.zip
That download path could not be verified. Check it before competition day.

BEFORE COMPETITION DAY
----------------------
1. Copy these FOUR supplied files into the IRSEC repository's Ansible folder:
   setup.sh, inventory.ini, install-scripts.yml, ansible.cfg
   Keep the existing Ansible/scripts_linux/, AuditingScripts/, and yara/ folders.
2. Package the WHOLE repository so it extracts to IRSEC/Ansible/.
   Example: from the parent folder of IRSEC, run:
       zip -qr irsec-toolkit.zip IRSEC/
3. Put irsec-toolkit.zip alongside index.html in the Cloudflare Pages site.
4. Test that https://f1-sh.duckdns.org/irsec-toolkit.zip downloads correctly.
5. Test the workflow against your own lab machines, not competition hosts.

ON THE AUTHORIZED UBUNTU/DEBIAN CONTROLLER
-----------------------------------------
1. Install download tools:
       sudo apt update
       sudo apt install -y curl unzip

2. Download:
       curl -fL --retry 3 -o irsec-toolkit.zip \
         https://f1-sh.duckdns.org/irsec-toolkit.zip

3. Extract and enter Ansible folder:
       unzip irsec-toolkit.zip
       cd IRSEC/Ansible

4. Run interactive setup:
       bash setup.sh

5. Answer prompts:
   - Confirm this is an authorized controller.
   - Allow installing Ansible, sshpass, python3-winrm if needed.
   - Enter Linux username and Windows username (may be the same).
   - Enter ONE shared default password, hidden while typing.
   - Choose a host or group to deploy to.
   - Review connection tests; type DEPLOY to continue.

6. Verify Linux target files (example):
       ssh YOUR_USERNAME@10.5.1.4 'ls -la /tmp/irsec-tools/scripts'
   Verify Windows files in C:\IRSEC-Tools\AuditingScripts.

WHAT SETUP DOES
---------------
- Installs dependencies on the CONTROLLER only, if you approve.
- Uses password-based SSH for Linux, password-based WinRM for Windows.
- Uses one temporary local password file (mode 0600), removed at exit.
- Copies Linux Bash scripts and YARA files; copies Windows AuditingScripts.
- Does NOT execute scripts, install services, run watchers, or rotate passwords.
- Does NOT create SSH keys or require Python on Linux targets.
- Linux files are placed in /tmp/irsec-tools (temporary; lost on reboot).

COMPETITION TARGETS
-------------------
Linux: pitlane, garage, grandstand, scrutineering
Windows: pitwall, teamradio, safetycar, transporters, stewards
Excluded: timing (protected Wazuh) and barrier (pfSense)

LIMITATIONS / SAFETY
--------------------
- Only use an approved controller during permitted competition periods.
- The timing Wazuh host is protected: get White Team approval before using
  it as a controller, installing packages, or storing secrets there.
- Only teamradio is explicitly known to expose WinRM. Other Windows hosts
  may not be reachable; don't enable new services without permission.
- Windows may require DOMAIN\username or HOST\username for authentication.
- Linux requires working SSH password login and the base64 command.
- Linux account needs write access to /tmp; Windows account needs permission
  to write C:\IRSEC-Tools. No sudo escalation is attempted on targets.
- Preserve SSH host-key checking. Confirm fingerprints with teammates.
- If a teammate rotates a password, that host stops authenticating with the
  old shared password; rerun setup with the new credentials as needed.
- Never put real passwords into public GitHub or Cloudflare files.
- Verify all Ansible results; partial failures are possible.
- The current watcher and inventorier still use different baseline paths.

TROUBLESHOOTING
---------------
404: Check Cloudflare Pages ZIP file name/path.
Missing directories: You packaged only the Ansible folder, not full IRSEC.
SSH authentication failed: Check username, password, and SSH configuration.
WinRM unreachable: Verify the service is allowed, configured, and reachable.
Python winrm missing: Install python3-winrm in Ansible's Python environment.
SSH host key failed: Verify host identity, then update known_hosts securely.
